# Evidence

Status: planned
Idea: none

## Goal

Every user-facing change ships with something a reviewer can look at without
re-running it: screenshots, a short capture, or an exact verification record,
attached where review happens — the PR body — or staged at
`.branch/evidence/<slug>.md` until a PR exists.

## Non-goals

- No guaranteed `before` capture — reaching the pre-change app (stash, base
  checkout) is gymnastics; a `before`/`after` pair only when the baseline is
  cheap. The fallback is always an honest verification record, never silence.
- No upload mechanics baked in — attaching uses whatever the forge supports via
  `gh`; no account for hosts that can't.
- Not a menu item — evidence is produced by a skill on demand and consumed by
  ship automatically.

## Approach

A 16th skill, `branch-evidence` — mirroring the research's `before-and-after`
(shape: a formatting skill; capture comes from whatever the host can do). It
writes a `## Evidence` section and saves captures under `.branch/evidence/`:

```markdown
## Evidence

| Artifact | What it shows | How produced |
|---|---|---|
| <file or text> | <one line> | <screenshot, recording, command> |
```

Capture ladder, honest about host variance: screenshot the changed surface if
browser tooling exists → short recording → the exact command and output that
proves it (always possible). Attach: `gh pr edit` the `## Evidence` section into
the PR body when a PR resolves (same resolution rules as `branch-tend`);
otherwise write `.branch/evidence/<slug>.md` — and `branch-ship`'s `pr` route
folds a staged file into the PR body automatically.

This is why it is a skill and not a ship step: evidence can be produced any time
after build, not only at ship.

- [x] 2. `templates/skills/branch-ship/SKILL.md` `pr` route: include the staged

- [x] 3. `templates/agent-block.md` directory line gains `.branch/evidence/`.
- [x] 4. Reinstall, advance this card, `Unreleased` CHANGELOG entry.
- [x] 5. Verify: `bun run typecheck && bun test && bun run build`; stage an
  evidence file for this feature (a text artifact — the skill has no visual
  surface) and confirm ship would pick it up.

## Test plan

- Automated: suite covers render of the new file; `info()` unchanged (evidence
  is per-work ephemeral, not counted).
- Manual: a staged `.branch/evidence/2026-10-04-evidence.md` documents this run.

## Risks and open questions

- `.branch/evidence/` may hold binaries — the repo owner decides whether to
  gitignore it; the skill does not prescribe.
- Evidence quality is host-dependent by design; the ladder guarantees the floor
  (a verification record) rather than the ceiling (a recording).
