# Triage

Status: planned
Idea: .branch/ideas/2026-10-03-triage.md

## Goal

`/branch-triage` decides whether a unit of work proceeds, and how. It classifies
each item as `ready` / `needs-plan` / `question` / `drop`, checks it against the
existing work for duplicates, and records the verdict on the work card. Run with
no argument, it processes every card still at `Status: captured`.

## Non-goals

- No new statuses — `triaged` and `dropped` already exist in the card enum.
- No semantic dedupe — title/slug comparison only.
- Triage never edits source files or runs builds; it reads `.branch/` and the
  open-PR list and writes only the card.
- No batch approval UI — one verdict per card, shown as a summary at the end.

## Approach

One new dispatcher skill, `branch-triage` — triage is a pipeline stage with its
own invoke point, and a route on `branch-idea` would overload that dispatcher
(and later intake sources won't come through ideas). Verdicts live in a
`## Triage` section appended to the card; `Status:` becomes `triaged`, or
`dropped` on a drop verdict.

Rubric, from the research (small, well-specified work succeeds most often):

- `ready`: fits one sitting, done-condition writable in one line, no
  auth/billing/data surface, no open questions → suggest `/branch-build`.
- `needs-plan`: worth doing, but multi-step or the approach is unclear →
  `/branch-plan`.
- `question`: missing information only the user has → the question is the
  deliverable; card stays `triaged`.
- `drop`: duplicate, obsolete, or not worth it — reason recorded; "not now" is a
  drop with a revisit note, the card stays in `.branch/work/`.

Dedupe: compare the subject to titles in `.branch/ideas/`, `.branch/plans/`,
`.branch/work/`, and `gh pr list` (only when `gh` is on PATH and the repo has a
remote). On a match, ask before classifying.

Reuses: card format + `Status:` enum from `branch-idea`, the `Key: value` and
transparency-line conventions, slug naming.

## Risks and open questions

- Verdicts are advisory — an agent may route a `ready` item through a plan
  anyway. Fine: the card records the decision, not enforces it.
- Empty-queue behavior must be a clear "nothing to triage", not an error.
